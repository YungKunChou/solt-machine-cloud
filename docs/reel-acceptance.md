# 雙滾輪改修驗收

實作日期：2026-09-25。基準版本：`eac91a1`，通訊協定：2。

## 已完成的功能檢查

`npm.cmd test`：102 項通過。測試包括：

- 實際程式的運動函式：1～10 個選項、每個目標、五種小數起點、四種邏輯位置（包含約十億格），共 1,100 組、111,100 個減速取樣點。檢查有效終點、前進方向、速度單調、距離及時間界線。
- 所有 1～10 項的雙輪回合，兩欄不同筆數、同名獎品與重複數量；每個選項保持獨立 ID，畫面目標與入榜結果一致。
- 立即停止、重複停止、自動期限已過但計時器未執行、回呼延誤後補算全部階段、過期回呼，以及只啟動一輪就離線。
- 等待者重連加入隊尾、回合中恢復身分與控制權、已完成／被移出者不重排、同一憑證的新連線接管。
- 玩家與觀眾共用的實際播放器：固定 9 個節點、不同格高、縮放只改像素、晚加入及背景返回不從頭播放、有效選項置中核對。
- 前景回合固定校時基準；正負校時更新不改正在播放的曲線。新版快照先到、舊版操作確認後到時，操作可結束等待且快照不倒退。
- 重連前的舊操作回覆不能解除重連後的新操作等待；舊協定拒絕操作，私有憑證與未公布結果不出現在快照中。
- 姓名輸入、移出玩家、設定 ID／上限／草稿、歷史零筆排除與 CSV 回歸。
- 在獨立的隨機本機埠執行真實 HTTP／Socket.IO 測試：建立房間、主持人與玩家加入、雙輪停止、觀眾晚加入取得相同計畫、玩家斷線後後端仍完成、重連保持已完成身分。測試結束即關閉，不影響原本啟動的活動。

以上是程式與功能驗證，沒有執行瀏覽器截圖、自動視覺驗證或真實跨裝置時間差量測。規劃階段的 11,110 組，以及使用者提供的 27,775 組檢核，屬不同來源，不併入此次實作測試數量。

啟動修正：本機啟動器原先比對已更換的後端首頁文字，造成服務已監聽仍判定逾時；現改用 `/health` 檢查服務識別、就緒狀態及協定版本，並新增兩項回歸測試。已實際執行本機啟動流程，確認顯示「本機前後端已就緒」、新遊戲模組可讀取，輸入 `q` 後前後端正常結束、釋放 3001 與 8080 埠。

後續操作修正：QR Code 建立前清除提示節點；取消每輪重新洗牌，新增由後端提供的各輪初始位置，保留上一輪中央與周邊可見項目。尚未啟動的一輪維持相同位置，手動及自動啟動使用同一起點。設定變更則先更新待機顯示，不延到按拉桿才換項目。僅手動煞停確認後，拉桿先歸位 30%，等畫面停止後再完全歸位；自動煞停維持拉下狀態直到停止。新增七項功能測試；視覺效果待使用者人工確認。

## 開始人工確認

設定保存追加驗證：已檢查最新一筆覆蓋、重新讀取、重複選項、清除後回到預設來源、損壞／封鎖／容量不足處理、僅儲存成功才保存、建立新房間時套用且取得新 ID，以及回復預設的成功、失敗與回合鎖定。人工確認時請修改並儲存後建立另一個活動，再測試「回復預設」；按鈕採低調灰綠色，位於「編輯設定」右側。

1. 若舊活動尚有需要保存的名單，先匯出 CSV。新版不能接續重啟前的記憶體房間。
2. 在原啟動視窗輸入 `q` 結束服務，再雙擊「啟動本機抽獎.cmd」。新增模組需要重新啟動前端檔案服務，後端也必須更新。
3. 開啟 `http://127.0.0.1:8080`，重新整理首頁並建立新房間。
4. 原分頁為莊家；複製只帶房間 ID 的網址到同一台電腦另一個瀏覽器，登記玩家姓名。另開分頁作觀眾。不同瀏覽器的主持權及本機歷史不共用。
5. 手機測試須使用前後端均更新的 HTTPS 測試部署；目前本機服務只綁定 127.0.0.1，手機不能直接使用這個網址。這次尚未發布。

## 同步時間量測

初版正常前景驗收條件：同一台電腦的兩個目前版本瀏覽器、相同本機後端、視窗均可見，選取校時樣本 RTT 不高於 100 毫秒；1、3、5、10 項各做至少 5 回合。記錄瀏覽器版本、螢幕更新率、測試時間、每次操作往返與結果。

初始調校目標為正常前景可見停止時間差不超過 150 毫秒；這是待量測的驗收目標，不是已證明的跨裝置保證。背景恢復、網路明顯延遲及裝置休眠另列，不用連續動畫的門檻判定。每案結果 ID 與光榮榜一致、單回合僅入榜一次仍是必要條件。

供協助驗收者使用：頁面提供唯讀 `window.LOTTERY_DIAGNOSTICS()`，包含活動／計畫識別、最近選取樣本 RTT、RTT 一半的校時不確定性估計、樣本年齡、待套用校正量、估計伺服器時間、最近繪製位置與共同停止時間，不含私有憑證。RTT 一半僅為估計，非網路非對稱時的精準誤差保證。不同頁面在不同時刻讀取的位置不能直接相減；須對齊共同時間，並搭配使用者人工同畫面錄影逐格核對實際可見停止時間。

程式每 30 秒取得新樣本，正常回合不直接套用；偏差超過 150 毫秒則取得最新快照，以恢復情境處理。恢復優先確保權威進度及結果，不宣稱補播所有錯過的畫格。

## 保存與發布邊界

後端尚未使用資料庫，也沒有閒置房間清理；重啟會失去房間與尚未由莊家保存的結果。Local Storage 是目前瀏覽器的歷史快照，不是原房間備援。私有參加者憑證僅提供原分頁恢復，不代表同一真人只能參加一次。

待使用者人工確認動畫後，再依明確指令 Commit／Push。正式發布須在活動結束後，前端及後端成套更新，所有人重新整理並建立新房間。
