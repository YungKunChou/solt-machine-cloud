# 雲端雙滾輪抽獎

## 本機開發

Windows 使用者直接雙擊根目錄的 **`啟動本機抽獎.cmd`**：

1. 檢查 Node.js，缺少套件時自動安裝（需要網路）。
2. 啟動本機前端與後端，等候就緒後自動開啟預設瀏覽器。
3. 再次雙擊時沿用同一專案已啟動的服務，不重複開啟伺服器。
4. 保留啟動視窗；結束時輸入 `q` 再按 Enter，或按 Ctrl+C，同時停止前後端。

若埠號被其他程式占用，啟動視窗會顯示原因，不會強制關閉其他程式。第一次使用需先安裝 Node.js（含 npm）。直接雙擊 `index.html` 仍會使用 Render 正式後端；要測試本機前後端，請使用上述啟動檔。

也可在此專案根目錄開啟終端，第一次執行：

```powershell
npm.cmd ci
```

啟動前端與後端：

```powershell
npm.cmd run dev
```

開啟 <http://127.0.0.1:8080>。按 Ctrl+C，或輸入 `q` 後按 Enter，關閉前後端；修改後端後需重新啟動，修改前端後重新整理頁面。需要可用的 Node.js 與 npm。

`config.js` 讓 localhost、127.0.0.1 與 IPv6 loopback 主機名使用本機後端，其餘主機名使用正式 Render 網址。要測試本機後端，請使用上述本機網址；區網 IP 尚未配置。本機前端只綁定 127.0.0.1，後端沿用原有監聽設定；手機測試尚未配置。

字型、Tailwind、Socket.IO 瀏覽器套件、QR Code 與 YouTube 仍從網路載入，因此並非完全離線版。

## 每次修改與發布

1. 檢查並保存未提交修改，取得 origin 最新版本，將最新 main 整合到修改分支。
2. 本機修改與啟動測試；檢查前後端差異，僅提交需要發布的檔案。
3. 推送修改分支並透過 Pull Request 檢查，確認發布時再合併到 main。
4. 在 GitHub Actions 確認 Pages 發布成功；在 Render 確認部署成功且提交版本正確。
5. 若已關閉 Render 自動部署，只在有後端改動時手動部署。
6. 開啟正式網站建立新房間，確認加入、抽獎、同步與匯出。

前後端通訊規則若同時改動，需安排向後相容的發布順序。活動進行中避免部署：進行中的房間只存在後端記憶體，重啟或部署後無法繼續原房間；主持人瀏覽器已保存的活動快照仍可查看、匯出。重要名單仍建議匯出 CSV 備份。

目前使用第 2 版通訊協定，舊版抽獎及單欄設定事件均拒絕操作。GitHub Pages 與 Render 各自部署，不保證同時完成；請在活動結束後配套更新，確認兩端均完成，再重新整理首頁並建立新房間。

## 批次編輯獎項與數量

1. 主持人按「編輯設定」，兩欄同時進入編輯狀態，可直接修改多行。
2. 各欄上方「新增」加入空白列；每筆右側的細框「X」直接刪除該筆，無需勾選。
3. 刪除後可按「復原」還原該欄最近一次刪除；儲存前的變更只存在草稿。
4. 按「儲存全部變更」一次套用兩欄，並同步至參加者。按「取消」則捨棄本次全部修改。
5. 每欄須保留 1 至 10 筆（數量的數值不以 10 為上限），獎項名稱不可空白且最多 120 字，數量須為正整數。重複數量會保留，增加該數量的抽中機率。

玩家已開始本輪抽獎時可編輯草稿，但須等本輪完成後才能儲存；參加者加入或排隊更新不會覆蓋草稿。連線中斷或儲存失敗時保留目前頁面的草稿；草稿沒有寫入硬碟，關閉或重新整理仍可能遺失。主持人使用原分頁重新連線後，會恢復管理權限。

桌面採左右兩欄，手機改為上下排列；編輯時下方保留取消與儲存操作。

儲存成功後，獎項與數量會覆蓋此瀏覽器 Local Storage 的同一筆「最新設定」，不保留設定版本清單。從 VIP 首頁建立新活動時，自動使用最新設定；新房間仍由後端驗證並為每筆選項產生新識別碼。同名獎項與重複數量保持各自一筆。未儲存草稿、失敗的儲存、一般玩家收到的同步資料，以及單純重新開啟舊房間，都不覆蓋最新設定。

「編輯設定」右側新增灰綠色「回復預設」，直接將目前活動及最新設定回復為五種預設咖啡、數量 1／2／3。抽獎進行中、離線及送出中不能回復；編輯草稿時隱藏此按鈕，請先儲存或取消草稿。儲存空間不足或被封鎖時，活動仍可更新，但設定區會提示無法保存供下次使用。

最新設定依網站來源與後端隔離，換瀏覽器或網站網址不共用。清除網站的 Local Storage 後，下一個新活動使用預設值；單純清除瀏覽紀錄是否包含網站資料取決於瀏覽器選項。「清除歷史紀錄」只刪歷史活動，不刪最新設定；回復預設也不會改寫舊活動的歷史快照。已建立房間繼續使用自身的後端設定，重新整理不會拿其他活動的最新設定覆蓋正在進行的活動。

目前設定區與抽獎區共用相同最大寬度（1024px），獎項名稱與數量在一般及編輯狀態均使用 25.5px 字體、60px 列高；驗證錯誤訊息可讓列高延展。只保留中川政七風格，已移除 ROG 樣式與風格切換按鈕。後續版面修改預設交由使用者人工確認。

## 主持人重連與重複加入

- 建立房間時，後端以安全亂數產生主持人憑證；首頁先將憑證保存在該分頁的 `sessionStorage`，再開啟抽獎頁。憑證依後端與房間分開保存，不會放入分享網址、QR Code 或房間廣播。
- 原瀏覽器的原分頁重新整理、短暫斷線後重新連線，都會帶上憑證恢復主持權。即使玩家比主持人先連入，玩家仍只會加入隊伍。
- 主持人離線時保留恢復資格，其他玩家不會自動升為主持人；當前玩家的回合、獎項設定及排隊順序不受主持人重連影響。
- 同一憑證建立新主持連線時，權限移至新連線。舊主持分頁會顯示提示並停止連線，避免兩個分頁輪流搶回權限；舊連線稍後離線也不會清除新主持人的身分。
- 同一連線重複加入同一房間，只回傳現況，不清空姓名、不重排隊伍、不重置回合。主持人及已完成抽獎的玩家不會因重送加入請求而進入隊伍。
- 分頁儲存被瀏覽器封鎖時，首頁會提示，並停止進入無法恢復主持權的房間。關閉原分頁、清除儲存、換瀏覽器或換裝置，均不保證保留主持憑證；目前沒有跨裝置移交或找回機制。

此功能需要新版 `index.html`、`slot-machine.html`、`room-session.js` 與後端一起更新；本機啟動服務也須重新啟動，才能提供新增檔案。請在啟動視窗輸入 `q` 停止，再雙擊「啟動本機抽獎.cmd」，重新整理首頁並建立新房間。重啟仍會清除原房間及紀錄，需保留的得獎名單請先匯出。

## 驗證與現有限制

以多個瀏覽器分頁模擬主持人與參加者，檢查建立房間、命名、排隊、兩個滾輪、觀眾動畫、CSV 匯出與重新整理情境。

執行 `npm.cmd test` 可跑共用運動模型、回合期限、重連、權限、設定與歷史保存，以及前端操作／播放器測試。前端採受控 DOM 與通訊事件，沒有自動瀏覽器截圖，實際動畫自然度及跨裝置時間差仍由人工驗收。

新版回合規則：

- 每欄 1～10 個獨立選項 ID，同名／同數值仍是不同項目，每筆等機率；循環顯示不參與抽選。
- 設定未變更時，各輪沿用相同顯示順序，從上一輪停穩的位置接續啟動，不重新洗牌或跳回第一項；另一輪尚未啟動時保持原畫面。儲存新設定時先更新待機顯示，下一次直接由新設定的可見位置開始。
- 收到手動停止計畫後，拉桿先歸位 30%；該輪畫面停止後才完成剩下的 70%。自動停止時維持完全拉下，滾輪停穩後才一次歸位。停止來源由後端固定，逾期才收到的手動請求不會把已成立的自動停止改成手動。
- 第一個滾輪啟動成功即成立回合。每輪第一次啟動鎖定後端結果，在停止計畫發布前不公開結果。主持人、玩家與觀眾使用相同排列、時間及減速計畫。
- 接受啟動後預留 250 毫秒共同開始；手動停止的減速起點為「接受停止後 250 毫秒」與「開始後 500 毫秒」較晚者。停止路徑向前移動至少 12 格，減速約 2～3.667 秒（上界不含）。
- 各輪開始後 4 秒排定自動停止，再預留 250 毫秒開始減速。第一輪開始後 10 秒，替未啟動的另一輪排定開始時間，再預留 250 毫秒；不是整回合 10 秒內結束。
- 已成立回合不因抽獎者或主持人離線取消；後端按期限完成並且只入榜一次，不等待瀏覽器回報停止。處理指令前先補算已到期狀態，計時器晚執行不延長期限。
- 參加者憑證保存在原分頁 sessionStorage，依後端、房間與活動隔離。未開始者斷線即退出隊伍，重連恢復身分並加入隊尾；已成立回合恢復原進度；已完成或被移出者只觀看，不重新排隊。
- 同一憑證的新連線接管操作權，舊連線停止使用；此匿名身分不等於員工身分驗證，換瀏覽器或清除分頁資料仍可能建立新參加者。
- 正常前景播放期間固定時間基準，回合間更新；重連、背景返回或明顯校時偏差時取得最新快照恢復進度。視窗縮放只換算格高，不改路徑或結果。
- 操作確認依 operationId 完成；附帶快照另按活動及 stateVersion 套用。較舊的成功回覆仍會解除等待，但不能覆蓋新畫面。

詳細規則見 [改修主計畫](docs/reel-rework-plan.md)，人工步驟見 [驗收清單](docs/reel-acceptance.md)。本次尚未完成真實瀏覽器視覺與跨裝置同步量測，不能將功能測試通過視為視覺驗收。

後端持久儲存與閒置房間清理不在本次範圍。後端重啟仍會失去房間；主持人離線期間完成的結果，要等其重連收到快照後才可能寫入本機歷史。如果在保存前後端已重啟，該筆結果仍可能遺失。Commit 與 Push 僅依使用者另外下指令執行。

## 本機保存與歷史活動

- 主持人收到後端確認的第一筆抽獎結果後，才自動把活動設定、得獎名單、建立及最後儲存時間寫入 Local Storage；零筆抽獎紀錄的活動不保存。舊版已保存的零筆活動不列入歷史清單及數量，原資料不自動刪除。每場活動有獨立識別碼，新活動不覆蓋舊活動；排隊及動畫更新不會改動最後儲存時間。尚未送出的設定草稿不包含在保存內容內。
- 首頁 VIP 按鈕下方提供「歷史活動（數量）」。遊戲頁不顯示歷史活動入口與保存訊息，主持人端仍持續自動保存。清單由新到舊排列，可查看得獎資料、展開獎項／數量設定及匯出 CSV。手機改為卡片列表。
- 「清除歷史紀錄」先顯示刪除數量與確認畫面，取消不改動資料。使用 Web Locks 保護同一網站其他主持人分頁正在使用的活動；關閉或離開主持人頁面後解除保護。即使確認畫面開啟後紀錄被更新或重新使用，也會保留該筆。主持人憑證、其他網站資料、已下載 CSV 不會被清除；不支援 Web Locks 的環境可保存、讀取、匯出，但停用清除。
- 保存僅限目前瀏覽器、使用者設定檔及網站網址，並依後端分開；另一瀏覽器、無痕視窗或改用 localhost／127.0.0.1／不同埠號不共用紀錄。清除網站資料也會移除歷史活動，重要資料請另存 CSV。
- 不會為騰出空間自動刪除舊紀錄；異常紀錄保留原資料。VIP 首頁的歷史清單遇到讀取或清除問題會顯示提示；遊戲頁依介面設定不顯示保存訊息，因此重要活動仍請匯出 CSV 備份。CSV 使用 UTF-8 BOM，支援逗號、引號、換行及試算表公式前綴處理。
- 歷史紀錄是只供查看及匯出的快照，並非恢復原房間、主持人憑證或排隊狀態。更新前已結束且未保存的活動不會自動補入。

此功能新增後端活動識別碼及建立時間，須更新前後端。本機請先匯出進行中的名單，在啟動視窗輸入 `q` 結束後，再雙擊「啟動本機抽獎.cmd」並建立新活動。新版頁面無法確認第 2 版協定時會阻擋加入，請配套更新前後端。新增的前端資源也需要重新啟動本機檔案服務才會提供。

## 莊家移出尚未開始的玩家

- 採用示範稿第 1 組並依後續調整縮短列表：排隊編號、姓名、右側灰褐細框「X」方形移出按鈕；未填姓名提示與玩家編號同行，玩家之間不加分隔線。抽獎中的列有淡底與鎖頭。只有莊家顯示移出按鈕，點按直接送出，不顯示二次確認或成功提示。一般列高 40px，列表最多約顯示三列，其餘可捲動。
- 尚未開始的隊首及其他等待玩家都可移出；隊首移除後由下一位接續。後端接受任一滾輪的第一次抽獎請求後，該玩家直到本輪結束前均不可移出，包括只停完一個滾輪的情況。
- 後端逐次驗證當前莊家、目標參加者及回合狀態。以穩定參加者識別指定目標，不使用會變動的排隊序號。移出與抽獎同時發生時，以後端先接受的操作為準；其他玩家順序、進行中的回合、獎項設定和得獎紀錄保持原樣。
- 被移出者仍連線觀看，不能改名或抽獎。`room-session.js` 為參加者保存原分頁的匿名識別及移出狀態（依後端、房間與活動隔離）；後端私下保存已移出識別，因此即使漏接移出通知，重新整理或重連仍只加入觀看模式。私有憑證不放入分享網址、QR Code、公開房間狀態或 Local Storage 活動快照；公開參加者 ID 用來對應排隊及得獎紀錄。
- 無法保存分頁身分或紀錄損壞時，只加入觀看模式並提示。觀看模式遇到舊後端會停止連線並提示更新，避免意外重新排隊。
- 此功能防止原分頁自動重入，並非真人封鎖。新的瀏覽器、不同設定檔、清除分頁資料等仍可能重新加入。沒有加入批次移除、復原或封鎖名單。

需更新前後端並重新啟動本機服務，讓新事件、`queue.css` 與圖示生效；請在本輪活動結束並備份需要的名單後重啟。版面按專案偏好由使用者人工確認，功能以自動測試檢查。

## 遊戲頁排列與玩家提示

- 桌面版為左側 QR Code／排隊列表／光榮榜、右側拉霸；手機版依序為 QR Code（僅莊家顯示）、拉霸、排隊列表、光榮榜，讓兩個列表位於最下方。
