# 雲端雙滾輪抽獎

## 本機開發

Windows 使用者直接雙擊根目錄的 **`啟動本機抽獎.cmd`**：

1. 檢查 Node.js，缺少套件時自動安裝（需要網路）。
2. 啟動本機前端與後端，等候就緒後自動開啟預設瀏覽器。
3. 再次雙擊時沿用同一專案已啟動的服務，不重複開啟伺服器。
4. 保留啟動視窗；結束時輸入 `q` 再按 Enter，或按 Ctrl+C，同時停止前後端。

若埠號被其他程式占用，啟動視窗會顯示原因，不會強制關閉其他程式。第一次使用需先安裝 Node.js（含 npm）。直接雙擊 `index.html` 仍會使用 Render 正式後端；要測試本機前後端，請使用上述啟動檔。

也可在此專案根目錄開啟終端，第一次執行：

```powershell
npm.cmd ci
```

啟動前端與後端：

```powershell
npm.cmd run dev
```

開啟 <http://127.0.0.1:8080>。按 Ctrl+C，或輸入 `q` 後按 Enter，關閉前後端；修改後端後需重新啟動，修改前端後重新整理頁面。需要可用的 Node.js 與 npm。

`config.js` 讓 localhost、127.0.0.1 與 IPv6 loopback 主機名使用本機後端，其餘主機名使用正式 Render 網址。要測試本機後端，請使用上述本機網址；區網 IP 尚未配置。本機前端只綁定 127.0.0.1，後端沿用原有監聽設定；手機測試尚未配置。

字型、Tailwind、Socket.IO 瀏覽器套件、QR Code 與 YouTube 仍從網路載入，因此並非完全離線版。

## 正式檔案

- `index.html`：入口與建立房間。
- `slot-machine.html`：抽獎介面。
- `settings-editor.js`、`settings.css`：獎項與數量的批次編輯介面。
- `settings-rules.js`：前後端共用的設定驗證。
- `config.js`：前後端連線設定。
- `啟動本機抽獎.cmd`、`scripts/start-local.cjs`：Windows 一鍵啟動與自動開啟瀏覽器。
- `index.js`：正式後端，Render 使用此根目錄檔案。
- `package.json`、`package-lock.json`：後端套件與本機啟動指令。
- `scripts/dev.cjs`：只用於本機啟動，提供明確允許的前端檔案；新增前端資源時請更新其 publicFiles 清單。

## 每次修改與發布

1. 檢查並保存未提交修改，取得 origin 最新版本，將最新 main 整合到修改分支。
2. 本機修改與啟動測試；檢查前後端差異，僅提交需要發布的檔案。
3. 推送修改分支並透過 Pull Request 檢查，確認發布時再合併到 main。
4. 在 GitHub Actions 確認 Pages 發布成功；在 Render 確認部署成功且提交版本正確。
5. 若已關閉 Render 自動部署，只在有後端改動時手動部署。
6. 開啟正式網站建立新房間，確認加入、抽獎、同步與匯出。

前後端通訊規則若同時改動，需安排向後相容的發布順序。活動進行中避免部署：目前房間與得獎紀錄只存在記憶體，後端重啟或部署後會消失；先匯出需要保存的名單。

這次批次編輯新增 `updateSettings` 通訊事件，正式發布時須同時包含前端與後端。建議先讓 Render 更新成功，再使用新前端；新後端保留舊版的單欄更新事件。GitHub Pages 和 Render 的自動部署各自進行，並不保證同時完成；若新前端先發布，批次儲存會等候逾時並保留草稿，請待後端部署完成再試。

## 批次編輯獎項與數量

1. 主持人按「編輯設定」，兩欄同時進入編輯狀態，可直接修改多行。
2. 各欄上方「新增」加入空白列；勾選多筆後按「刪除選取」，也可用工具列的勾選框全選。
3. 刪除後可按「復原」還原該欄最近一次刪除；儲存前的變更只存在草稿。
4. 按「儲存全部變更」一次套用兩欄，並同步至參加者。按「取消」則捨棄本次全部修改。
5. 每欄須保留 1 至 100 筆，獎項名稱不可空白且最多 120 字，數量須為正整數。重複數量會保留，增加該數量的抽中機率。

玩家已開始本輪抽獎時可編輯草稿，但須等本輪完成後才能儲存；參加者加入或排隊更新不會覆蓋草稿。連線中斷或儲存失敗時保留目前頁面的草稿；草稿沒有寫入硬碟，關閉或重新整理仍可能遺失。既有主持權重新連線問題尚未修復。

桌面採左右兩欄，手機改為上下排列；編輯時下方保留取消與儲存操作。

目前設定區與抽獎區共用相同最大寬度（1024px），獎項名稱與數量文字已放大 50%，一般列高維持 72px。只保留中川政七風格，已移除 ROG 樣式與風格切換按鈕。後續版面修改預設交由使用者人工確認。

## 驗證與現有限制

執行 `npm.cmd test` 可跑批次設定的 9 項測試，涵蓋一次套用兩欄、無效資料不局部寫入、主持權、版本衝突、抽獎中鎖定、回合完成／離線解鎖及舊版事件相容性。這些測試不代表整個抽獎流程都已驗證。

已知的主持權重連、重複抽獎、姓名驗證及提前完成回合等問題，仍需後續修復。本次補上當前玩家離線時清除未完成回合，避免批次設定一直被鎖定。
