# 雲端雙滾輪抽獎

## 本機開發

Windows 使用者直接雙擊根目錄的 **`啟動本機抽獎.cmd`**：

1. 檢查 Node.js，缺少套件時自動安裝（需要網路）。
2. 啟動本機前端與後端，等候就緒後自動開啟預設瀏覽器。
3. 再次雙擊時沿用同一專案已啟動的服務，不重複開啟伺服器。
4. 保留啟動視窗；結束時輸入 `q` 再按 Enter，或按 Ctrl+C，同時停止前後端。

若埠號被其他程式占用，啟動視窗會顯示原因，不會強制關閉其他程式。第一次使用需先安裝 Node.js（含 npm）。直接雙擊 `index.html` 仍會使用 Render 正式後端；要測試本機前後端，請使用上述啟動檔。

也可在此專案根目錄開啟終端，第一次執行：

```powershell
npm.cmd ci
```

啟動前端與後端：

```powershell
npm.cmd run dev
```

開啟 <http://127.0.0.1:8080>。按 Ctrl+C，或輸入 `q` 後按 Enter，關閉前後端；修改後端後需重新啟動，修改前端後重新整理頁面。需要可用的 Node.js 與 npm。

`config.js` 讓 localhost、127.0.0.1 與 IPv6 loopback 主機名使用本機後端，其餘主機名使用正式 Render 網址。要測試本機後端，請使用上述本機網址；區網 IP 尚未配置。本機前端只綁定 127.0.0.1，後端沿用原有監聽設定；手機測試尚未配置。

字型、Tailwind、Socket.IO 瀏覽器套件、QR Code 與 YouTube 仍從網路載入，因此並非完全離線版。

## 正式檔案

- `index.html`：入口與建立房間。
- `slot-machine.html`：抽獎介面。
- `settings-editor.js`、`settings.css`：獎項與數量的批次編輯介面。
- `settings-rules.js`：前後端共用的設定驗證。
- `config.js`：前後端連線設定。
- `room-session.js`：保存原分頁的主持人憑證，供重新整理與斷線重連使用。
- `啟動本機抽獎.cmd`、`scripts/start-local.cjs`：Windows 一鍵啟動與自動開啟瀏覽器。
- `index.js`：正式後端，Render 使用此根目錄檔案。
- `package.json`、`package-lock.json`：後端套件與本機啟動指令。
- `scripts/dev.cjs`：只用於本機啟動，提供明確允許的前端檔案；新增前端資源時請更新其 publicFiles 清單。
- `manual.html`：原有說明頁，其中「永久保存資料庫」的敘述尚未實作。

本機 `.local-setup/original/` 保存整理前原始檔案（不含 node_modules）；`.local-setup/upstream/` 保存取得的 GitHub 檔案快照。`後台/` 及其他舊文件保留作參考並已排除於 Git，後續請修改根目錄正式檔案。

## 每次修改與發布

1. 檢查並保存未提交修改，取得 origin 最新版本，將最新 main 整合到修改分支。
2. 本機修改與啟動測試；檢查前後端差異，僅提交需要發布的檔案。
3. 推送修改分支並透過 Pull Request 檢查，確認發布時再合併到 main。
4. 在 GitHub Actions 確認 Pages 發布成功；在 Render 確認部署成功且提交版本正確。
5. 若已關閉 Render 自動部署，只在有後端改動時手動部署。
6. 開啟正式網站建立新房間，確認加入、抽獎、同步與匯出。

前後端通訊規則若同時改動，需安排向後相容的發布順序。活動進行中避免部署：目前房間與得獎紀錄只存在記憶體，後端重啟或部署後會消失；先匯出需要保存的名單。

這次批次編輯新增 `updateSettings` 通訊事件，正式發布時須同時包含前端與後端。建議先讓 Render 更新成功，再使用新前端；新後端保留舊版的單欄更新事件。GitHub Pages 和 Render 的自動部署各自進行，並不保證同時完成；若新前端先發布，批次儲存會等候逾時並保留草稿，請待後端部署完成再試。

## 批次編輯獎項與數量

1. 主持人按「編輯設定」，兩欄同時進入編輯狀態，可直接修改多行。
2. 各欄上方「新增」加入空白列；勾選多筆後按「刪除選取」，也可用工具列的勾選框全選。
3. 刪除後可按「復原」還原該欄最近一次刪除；儲存前的變更只存在草稿。
4. 按「儲存全部變更」一次套用兩欄，並同步至參加者。按「取消」則捨棄本次全部修改。
5. 每欄須保留 1 至 100 筆，獎項名稱不可空白且最多 120 字，數量須為正整數。重複數量會保留，增加該數量的抽中機率。

玩家已開始本輪抽獎時可編輯草稿，但須等本輪完成後才能儲存；參加者加入或排隊更新不會覆蓋草稿。連線中斷或儲存失敗時保留目前頁面的草稿；草稿沒有寫入硬碟，關閉或重新整理仍可能遺失。主持人使用原分頁重新連線後，會恢復管理權限。

桌面採左右兩欄，手機改為上下排列；編輯時下方保留取消與儲存操作。

目前設定區與抽獎區共用相同最大寬度（1024px），獎項名稱與數量文字已放大 50%，一般列高維持 72px。只保留中川政七風格，已移除 ROG 樣式與風格切換按鈕。後續版面修改預設交由使用者人工確認。

## 主持人重連與重複加入

- 建立房間時，後端以安全亂數產生主持人憑證；首頁先將憑證保存在該分頁的 `sessionStorage`，再開啟抽獎頁。憑證依後端與房間分開保存，不會放入分享網址、QR Code 或房間廣播。
- 原瀏覽器的原分頁重新整理、短暫斷線後重新連線，都會帶上憑證恢復主持權。即使玩家比主持人先連入，玩家仍只會加入隊伍。
- 主持人離線時保留恢復資格，其他玩家不會自動升為主持人；當前玩家的回合、獎項設定及排隊順序不受主持人重連影響。
- 同一憑證建立新主持連線時，權限移至新連線。舊主持分頁會顯示提示並停止連線，避免兩個分頁輪流搶回權限；舊連線稍後離線也不會清除新主持人的身分。
- 同一連線重複加入同一房間，只回傳現況，不清空姓名、不重排隊伍、不重置回合。主持人及已完成抽獎的玩家不會因重送加入請求而進入隊伍。
- 分頁儲存被瀏覽器封鎖時，首頁會提示，並停止進入無法恢復主持權的房間。關閉原分頁、清除儲存、換瀏覽器或換裝置，均不保證保留主持憑證；目前沒有跨裝置移交或找回機制。

此功能需要新版 `index.html`、`slot-machine.html`、`room-session.js` 與後端一起更新；本機啟動服務也須重新啟動，才能提供新增檔案。請在啟動視窗輸入 `q` 停止，再雙擊「啟動本機抽獎.cmd」，重新整理首頁並建立新房間。重啟仍會清除原房間及紀錄，需保留的得獎名單請先匯出。

## 驗證與現有限制

以多個瀏覽器分頁模擬主持人與參加者，檢查建立房間、命名、排隊、兩個滾輪、觀眾動畫、CSV 匯出與重新整理情境。

執行 `npm.cmd test` 可跑批次設定、後端回合規則、主持人重連、重複加入及前端事件流程測試。測試涵蓋一次套用兩欄、主持權恢復與轉移、憑證隔離與儲存失敗、重複加入不改動現況、版本衝突、雙滾輪先後停止、重複抽取、假造姓名、回合中改名、延遲通知、逾時重試及完成／離線解鎖。前端測試使用受控的 DOM 與通訊事件，不代表實際瀏覽器的視覺驗證。

抽獎回合已加入以下規則：

- 後端使用已登記的姓名；姓名去除前後空白，限 1 至 80 字，開始抽獎後本輪不能改名。
- 每個滾輪只產生一次結果，重複請求會返回同一結果；同一連線已得獎後改名，也不能再次抽獎。
- 前端收到抽獎確認才啟動動畫。兩個滾輪各自停止並收到後端確認後，才記錄得獎及換人。
- 停止與完成通知都核對回合編號；舊回合的通知不能完成新回合。重複完成通知不會新增第二筆得獎紀錄。
- 若抽獎或停止確認逾時，可再按該滾輪的拉桿重試；完成確認逾時，可按任一拉桿重試，不會重新抽取結果。
- 玩家離線時清除未完成回合，避免下一位沿用結果或讓設定一直被鎖定。

本輪變更新增 `reelStopped`、回合編號與抽獎回覆確認，必須配套更新前後端；舊版頁面不能完成新版回合。正式發布應安排在活動結束後，待前後端都更新完成，再請所有參加者重新整理並建立新房間。

永久保存與閒置房間清理仍待處理。玩家尚無帳號或可恢復的固定身分；排隊去重以同一連線為範圍，不合併不同分頁或不同瀏覽器的玩家。玩家重新整理後會取得新連線並重新排隊；目前也不能辨識斷線後換新名字的同一真人。

批次編輯已在本機瀏覽器驗證多行修改、新增、勾選刪除／復原、取消、無效數量提示，以及另一參加者分頁收到兩欄新設定；桌面、手機寬度與深色模式檢查見 `design-qa.md`。commit 與 push 僅在使用者另外下指令時執行。
